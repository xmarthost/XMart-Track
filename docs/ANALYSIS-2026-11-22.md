# Analysis: XMart Track vs the original Traccar code (2026-11-22)

Baseline: commit `738c9cf` "Initial import of Traccar server and web app" — the original Traccar code the
project started from. On 2026-11-21 morning (PKT) the WanWay G19S (IMEI 867857033265879) tracked live on this code.

## 1. Every server change since the original code

| File / setting | What changed | Effect on tracker communication |
|---|---|---|
| `protocol/Gt06ProtocolDecoder.java` | Status packet (0x13): when the level byte is `0xF0` (G19S), the byte after GSM is read as vehicle voltage (0.1 V) instead of an alarm code. Info packet 0x94/0x00 also stored as `power`. | Parsing only, after the packet is received. Replies and connections unchanged. |
| `protocol/Gt06ProtocolDecoder.java` (07a291f) | Stopped replying to location packets 0x10/0x12/0x22. | **Different from the original, which replied and worked. Reverted on 2026-11-22.** |
| `ProcessingHandler.java`, `database/NotificationManager.java` | A failing event/notification is logged and no longer stops the device's position queue; each notificator isolated; address-lookup errors caught. | Bug fix. In the original, any notification error froze all later positions of the device until restart. |
| `notificators/NotificatorFirebase.java` | High priority, `xm_alerts` channel, readable text. Bug: `titleFor()` called itself (StackOverflowError) — fixed in 242e711. | Only after events. **Firebase switched off on 2026-11-22.** |
| `notificators/NotificatorXmartWhatsapp.java`, `sms/*`, `NotificatorSms.java`, `NotificationFormatter.java`, templates | WhatsApp (XMart Sender), SMS gateway from the web, multi-number SMS, map link in SMS text. | Only after events. |
| `MainModule.java` | SMS manager reads the gateway from the web settings. | None. |
| `web/OverrideTextFilter.java` | Title/colour defaults. | None. |
| Config `decoder.timezone=UTC` | Tracker time read as UTC. | Corrects times only. Needed because after `GMT,E,5,0#` the tracker announced +5 h at login but still sent UTC (all times were 5 h early and alerts were skipped as "old"). |
| Config `status.ignoreOffline=gt06` | No offline status on each disconnect. | Status label only. |
| Config `processing.copyAttributes` (+power, adc1) | Voltage kept on later positions. | None. |
| Config `notificator.types` | web, sms, command, xmwhatsapp (firebase removed again). | None. |

## 2. Our mistakes

1. **Firebase `titleFor()` recursion (StackOverflowError)** — every ACC alert crashed the Firebase notificator; together with the
   original Traccar code that rethrows notification errors, the device position queue stopped (tracker online, location frozen).
   Fixed (242e711 + 98066e9). Firebase is now switched off until it is set up again.
2. **Blaming the tracker first** — the logs later showed the server-side queue freeze.
3. **Removing the reply to GPS packets (07a291f)** — based on a test with the car parked; it changed behaviour that worked in the
   original code. Reverted.
4. **Recommending tracker commands that changed its state** — `GMT,E,5,0#` (caused the 5-hour shift), `FACTORY#` (wiped the settings
   the tracker had from WanWay when it worked), `DEFENSE,0#`, `GPSON#`, `LANG` switches. The tracker is no longer in the state it
   was in on 2026-11-21 morning.
